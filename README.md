# 宠物救助故事创作台

内部编辑台 + 异步媒体任务 + 对外公开站点的全栈示例。技术栈：React 18 + Vite（前端）、Express 5 + JSON 持久化（后端，内部库与公开库物理分离两个数据文件）。

## 启动

```bash
# 后端（端口 4000）
cd server && npm start

# 前端开发（端口 5173，/api 已代理到 4000）
cd web && npm run dev
# 或使用已构建产物：cd web && npm run build，后端会直接托管 web/dist
```

打开「验收场景」页可一键执行四个指定场景；或跑自动化：

```bash
cd server && npm test     # 37 项端到端断言
```

## 核心设计

### 1. 内部记录 vs 公开稿（物理分离）
- `server/data/internal.json`：动物内部备注、真实称呼、芯片号、医疗细节、寄养地址、事件内部记录、角色内部资料、私密备注、任务、复核项、审计日志。
- `server/data/public.json`：只有已发布片段的**批准时冻结快照**。`/api/public/*` 只读这个文件；任何内部字段不经白名单投影都不可能出现（验收有物理文件级断言）。

### 2. 脱敏：白名单 + 文本检测的组合策略（两者串联，不互相替代）
- **公开字段白名单**：动物/事件/角色/媒体各有显式字段白名单（见 `redact.js`）；照片 EXIF 元数据独立白名单，仅保留 尺寸/机型/拍摄时间，GPS、作者、编辑软件等一律剥离。
- **文本检测**：对白名单字段内的自由文本做模式扫描并自动打码（手机号含分隔符变体、座机/400、邮箱、身份证、银行卡、家庭住址、GPS、微信号、车牌）。
- **覆盖面**：正文、字幕、旁白脚本、附带清单**四个文本面**以及**照片元数据**全部扫描，不只是页面文本。
- **机器无法可靠判断 → 人工复核队列**：人脸（肖像）、声音（自报信息/声纹，转写会漏字）、背景（门牌/快递单/校徽/地标）、组合推断。系统只标记、不声称已脱敏；复核项未全部处理则禁止批准。

### 3. 身份与领养状态持续变化
- 动物档案带 `version`，更新走 `If-Match` 乐观锁：两人同时改，后提交者得到 409 并看到对方的最新版本。
- 状态变为「领养完成」时联动：
  - 所有 `adoption_flyer` 招领片自动撤回（内部 + 公开库）；
  - 其排队中的导出/发布任务**自动取消**——不是只改档案而放任旧发布任务跑完；
  - 已在运行的任务在执行闸门重新校验，招领片+已领养会失败；
  - 已经生成的旧导出包不删除，但下载授权需逐包撤销（UI 明确提示）。

### 4. 异步媒体任务
- 类型：`sanitize`（生成脱敏预览，产出检测报告+复核项）、`export`（生成导出包）、`publish`（发布到公开库）。
- 幂等去重：同片段+同类型+同载荷哈希的排队/运行任务只保留一个，重复请求计入 `duplicate_requests`。
- **执行时闸门**：任务运行那一刻重新校验 撤回状态、照片许可、领养状态、批准状态、复核项、内容哈希与批准依据一致性。
- 导出包只含 `approved_preview` 冻结快照；导出排队期间补入的 `private_note`（独立内部字段）不会进入包。
- 开发/验收可 POST `/api/jobs/drain` 确定性排空队列。

### 5. 来源、批准依据与下载授权
- 每个公开片段携带来源记录（时间线事件/叙事角色，仅白名单字段）与批准依据（批准人、时间、五项勾选清单、内容哈希），公开页完整展示。
- 导出包下载须凭一次性授权 token；撤销后链接 403。
- **撤销授权不能删除外部下载者此前已保存的副本**——界面文案与边界说明均如实声明，不做虚假承诺。

## 验收场景（前端「验收场景」页 / `server/tests/acceptance.mjs`）
1. 两人同时改动物状态 → 409 冲突，先到者结果保留。
2. 照片被撤销许可 → 引用它的在途任务取消/失败、已发布稿撤回、批准失效。
3. 导出排队中补入私密备注 → 包内无备注、无任何内部字段或未打码 PII。
4. 重复投稿任务 → 合并到同一任务；不同载荷才新建。
另含：四面文本+EXIF 脱敏、复核未闭环禁止批准、领养联动撤回、公开库物理隔离断言、授权 200→撤销 403。
